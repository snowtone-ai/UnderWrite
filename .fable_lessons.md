# .fable_lessons.md — Fable 5 improvement session (2026-07-19)

## Product understanding
- UnderWrite = B2B SaaS for 築古住宅 (aged house) underwriting. Buyer-side agents/investors
  scan a property with phone photos + address; system returns purchase-cap price,
  renovation cost distribution (P10/P50/P90), hidden-damage risk, resale price, gross margin.
- Pain solved: buy-side pros must decide fast ("即日") whether an aged house is worth buying,
  without opening walls. The product sells *judgment* (目利き), not measurement.
- Payers: 買取再販業者 / 不動産投資家. Value = avoided bad purchases + speed of offers.

## Architecture invariants (must preserve)
- lib/ai/ = swappable AIProvider boundary (AI_PROVIDER env: gemini|claude|openai).
- lib/underwriting/ = pure deterministic math. Never imports lib/ai.
- lib/domain/ = versioned zod schemas (Finding et al.) at the AI boundary.
- lib/data/ = typed public-data clients (不動産情報ライブラリ), graceful degrade on missing key.
- Async photo analysis via next/server after(); client polls status endpoint.

## Lessons / findings (updated as work proceeds)
- (t0) Repo is small (~40 TS files); inline reading cheaper than subagent spawn.
- (t1) proxy.ts (Next16 middleware) gates auth at path level, but all API routes use the
  service-role client (bypasses RLS) — so per-route ownership checks are the real tenant
  boundary. Found IDOR: photos POST and status GET had no ownership check; any logged-in
  user could read any tenant's underwriting or inject photos/costs into others' scans.
- (t2) T15's "file size guard" was client-side only; server accepted any size/type, and
  `slot` was interpolated into the Storage path unsanitized (path injection).
- (t3) Engine edge case: purchaseCap clamps to 0 but verdict was still computed from the
  P50 margin → "conditional, buy below ¥0" nonsense. Rule: cap<=0 ⇒ nogo, dedicated headline.
  Bumped ENGINE_VERSION 1.0.0 → 1.1.0 (verdict semantics changed).
- (t4) MIME bug: PNG/HEIC uploads were sent to Gemini as image/jpeg. Changed AIProvider
  interface to accept {base64, mimeType}[] — interface change was cheap now, impossible later.
- (t5) UX: photo upload failures were console.warn only. Now: failed slots are reported,
  scanId is reused on retry, and only failed slots re-upload. Status API returns
  photo stats {total, failed}; result page shows a degraded-precision notice.
- (t6) Applied changes verified: 77 tests green (was 60), lint/typecheck/build pass.

- (t7) Opus review (fresh context) confirmed the diff and found one real defect I missed:
  storage blob orphaned when the photos-row insert fails after a successful upload.
  Fixed in 5f88115 with cleanup + regression test (78 tests green). Deferred (recorded):
  engine double-run race on concurrent polling — idempotent upsert makes it harmless.

- (t8) T17 frontend polish (PR#18, merged 8627ed7): pending status now carries
  {total, processed} so the wait screen shows real progress; client-side JPEG
  compression (2048px/q0.85, fallback to original) makes field uploads fast on 4G;
  retry button on result-page errors; UI types unified to lib/domain.
  Fresh Sonnet Tier1 review caught a bitmap.close() leak on the ctx-null path (dc6477a).
- (t9) Review pattern that works on this budget: implement inline → fresh-context
  subagent (Opus for security tier, Sonnet for UI tier) reviews the diff and applies
  fixes directly → main agent merges. Both reviews found exactly one real defect each.
